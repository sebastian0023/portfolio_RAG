# ADR-050: Phase 3 cost guard before Phase 4 quotas

Status: Accepted (Phase 3, owner decision 2026-10-04).

## Context

Phase 3 puts a working chat endpoint on the public internet. Cognito, Turnstile, per-user quotas, and the cost-abuse suite arrive in Phase 4. Until then the only planned brake is the pre-auth rate limit. At the worst case of $0.0088 per message (abuse-budgets.md) the global per-minute limit alone would allow about $0.35 to $0.53 a minute, or hundreds of dollars a day, if the endpoint were left open. The monthly budget kill switch lags billing by hours, so it cannot be the first line of defense (R-06, R-08).

## Decision

1. The API honors the SSM `chat_enabled` parameter now (ADR-027). It stays `false` except during bounded smoke windows that the owner opens and closes. A false, missing, or non-boolean value refuses every request before any paid call.
2. A temporary site-wide daily cap is a hard stop: `limits.globalPerDay` (30), reserved atomically in the counters table under the key `quota#global#<UTC date>`, before the first paid call, and never refunded. Phase 4 reuses the key for the global daily limit and adds the per-principal quotas beside it; the cap itself is then no longer a special case.
3. `limits.preAuthGlobalPerMinute` drops from 60 to 40. Bedrock allows 50 Haiku requests a minute across regions on this account (model-probe.md), so a global limit above that would let the provider, not this API, decide who is throttled. A contract test keeps the limit at or under 50.
4. The pre-auth rate limit runs before the `chat_enabled` check. It needs no model, so the limit and its concurrency behavior can be tested live with chat switched off, at zero cost. Every paid step still sits behind `chat_enabled`.
5. `accepted.quota` carries the site-wide daily counter (`principal: "guest"`, `left` = cap minus used). It is real and enforced, and needs no change to the ADR-048 contract. ADR-049 records the meaning.

## Consequences

- Worst-case exposure before Phase 4 is bounded by the daily cap: 30 messages, about $0.26 a day, whatever an abuser sends.
- When the site-wide count reaches zero the UI shows its guest copy for a signed-out visitor (it assumes a per-guest quota). The limit message itself ("Daily limit reached") is correct. Phase 4 replaces the numbers with real per-principal quotas.
- The daily cap is shared by all visitors, so a single abuser can use the whole day's allowance. That is the intended trade: availability for a portfolio site matters less than a spending ceiling.
- Switching `chat_enabled` takes effect within the config cache TTL (30 s), so closing a smoke window is not instant.
