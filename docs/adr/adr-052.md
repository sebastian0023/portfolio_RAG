# ADR-052: Turnstile guest pass

Status: Accepted (Phase 4, owner decision 2026-10-04). Builds on ADR-051.

## Context

With no accounts (ADR-051), the only thing between the open internet and a paid model call is the per-minute rate limit, the per-IP and global daily quotas, and `chat_enabled`. A script could still spend a whole day's quota in seconds from many addresses. A bot check raises that cost without asking visitors for anything. Turnstile tokens are single-use and valid for five minutes, so checking one on every question would add a visible delay to each message; checking once and remembering is friendlier.

## Decision

1. **Check once, then a signed pass.** The browser runs the Turnstile widget (invisible unless Cloudflare wants interaction, action `chat`) and sends the token to `POST /api/guest-pass`. The API verifies it with Cloudflare's siteverify (3 second timeout, the viewer IP as `remoteip`, the request id as the idempotency key, and the action must be `chat`) and returns a pass.
2. **The pass** is `v1.<base64url {k, exp}>.<base64url HMAC-SHA256>`. `k` is the fingerprint of the visitor's IP bucket (an IPv4 address or an IPv6 /64, as for the counters), and `exp` is one hour away. It is bound to the bucket, so it cannot be handed to another network, and it is signed with a server-only key, so it cannot be forged or extended. It is verified in constant time.
3. **Sending it.** Every chat request carries the pass in `X-Auth-Token`, the header the edge already forwards. A missing, malformed, forged, expired, or other-network pass is `guest_check_failed` (403), and the browser runs the check again. The pass lives in memory only.
4. **Where it sits.** The chat stages are: content type, byte cap, schema, config, trusted IP, per-minute rate, `chat_enabled`, **guest pass**, provider, quota. The pass is checked before anything is resolved or reserved, so a request without one costs nothing and uses no quota. The guest-pass route runs the same cheap stages first, so Cloudflare is only called for a well-formed request that passed the rate limit and `chat_enabled`.
5. **Secrets.** Two SSM SecureStrings, `turnstile_secret` and `guest_pass_key`. Terraform creates them holding the placeholder `unset` and never overwrites the value; the owner sets the real values with `put-parameter` (R-18). The API treats a missing, placeholder, or too-short value (the key needs at least 32 characters) as unavailable and refuses every request. They are read with decryption, cached for five minutes, and a failure is remembered for five seconds. Rotating `guest_pass_key` invalidates every pass.
6. **Failure handling.** Cloudflare timing out, answering badly, or reporting a platform error (a wrong secret, an internal error) is `unavailable` (503) and issues nothing; a refused, expired, or reused token is `guest_check_failed` (403). Error codes, tokens, passes, and addresses are never logged.
7. **Content-Security-Policy.** The page may load the widget from `https://challenges.cloudflare.com` in `script-src` and `frame-src`, and nowhere else. `connect-src` stays `'self'`.

## Consequences

- A visitor passes the check at most once an hour, and again if their network changes.
- A visitor on a shared network (an office, a carrier) shares one bucket's quota but each browser still holds its own pass.
- A leaked pass is useless to a different network and is dead within the hour; a leaked key is fixed by rotating it.
- The widget sitekey is public and goes in the SPA build; the secret never does.
- Turnstile's free plan has unlimited verifications and allows ten hostnames per widget. The CloudFront domain is added as a hostname; a custom domain later is one more entry.
