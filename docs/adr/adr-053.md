# ADR-053: Ingestion and index lifecycle

Status: Accepted (Phase 5, owner-approved plan 2026-10-04). Builds on ADR-018, ADR-019, ADR-020, ADR-031, ADR-033.

## Context

Retrieval needs an auditable public corpus, an index built from it, and a safe way to switch between indexes. The risks are R-02 (service limits), R-16 (wrong promotion or cleanup), R-14 (spend outside the kill switch), and R-17 (private data in a public corpus).

## Decision

1. **Corpus.** `knowledge/**/*.md`, each file with strict frontmatter: `id`, `title`, `kind` (experience, project, skill, education, faq), `lang: en`, `updated`, optional `url`, and `reviewed: true`. The owner approves every file. A `url` must be https on an allowlisted host (`ALLOWED_SOURCE_HOSTS`), checked at ingestion and again in the API.
2. **Public-safety scan.** Ingestion and a CI test reject emails, phone numbers, addresses, secrets, raw HTML, disallowed links, injection phrases, and literal `[n]` markers. Findings report the rule and line, never the matched text.
3. **Chunks.** At most 600 characters, split on sentences, with stable ids `<id>#<section>-<k>`. The chunk text is also the citation excerpt (ADR-048).
4. **Metadata.** Filterable keys are `sourceId`, `kind`, `lang`, `updated`, and the schema version, each well under the 2 KB service limit. Text, title, section, path, url, and the content hash are non-filterable.
5. **Manifest and index name.** A canonical JSON manifest holds every config (chunker, embedding, index, metadata schema) and the per-source file hashes and chunk ids, but no chunk text. Its SHA-256 names the index `chunks-<first 16 hex>`. S3 Vectors caps names at 63 characters.
6. **Indexes are not Terraform resources.** Terraform owns only the vector bucket (`prevent_destroy`, `force_destroy = false`, no bucket policy). The ingest tool creates indexes with 512 dimensions, cosine, float32.
7. **Ingest tool.** An operator-run CLI, dry-run by default, that runs only as the dedicated role `portfolio-v2-prod-ingest` (it checks the STS identity). It is capped (2,000 chunks, 400k estimated tokens, 5 requests per second, 1 retry) and idempotent: a complete index with the same hash is a no-op, and a pending one is resumed. It never writes SSM and never touches the active index. Completion is recorded in index tags (`IngestStatus=complete`, `ManifestSha256`) after the keys match the manifest and a self-query succeeds.
8. **Roles.** `portfolio-v2-prod-ingest` and `portfolio-v2-prod-eval` have no delete actions, and the eval role reads only the non-secret parameters. Both are kill-switch targets.
9. **Promotion.** Only the operator promotes. `promote` needs a passing eval report for the same index, manifest hash, and `llm_config`, less than 24 hours old. SSM has no compare-and-swap, so it re-reads the parameter version and requires the write to return the next version. The prior value is kept in parameter history.
10. **Retention.** Keep the active index and the two previous ones. `prune` never selects an index that was active in the last 10 minutes (longer than the 30 second config cache plus the Lambda timeout) or was created in the last 24 hours, and fails closed if history cannot be read.

## Consequences

- Changing any config or any file produces a new index, so identical text under different settings cannot collide (R-16).
- A failed ingest leaves a pending index that nothing reads.
- Reviewing the manifest in Git is enough to audit what was indexed, without publishing chunk text.
